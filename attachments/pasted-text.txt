ClashIQ — Complete Product & Development Specification

You are acting as a senior full-stack engineer, software architect, product designer, UI/UX specialist, and QA engineer.

Your mission is to research, design, build, test, and deliver a complete, production-ready website called ClashIQ.

This is not a request for a prototype or a landing page. Build a fully functional product.

Work independently, investigate technical uncertainties, make sensible engineering decisions, and solve problems without repeatedly asking me about minor implementation details.

---

1. Product Overview

ClashIQ is a Clash of Clans account comparison and analytics platform.

Users should be able to enter two Clash of Clans player accounts and compare their available statistics, progression, troops, buildings, heroes, and other relevant information side by side.

The product should go beyond displaying statistics. It should analyze account progression, identify strengths and weaknesses, and provide meaningful comparisons.

The entire product must focus exclusively on the Home Village.

Builder Base must be completely excluded from all comparisons, calculations, and interfaces.

Use the following technology stack unless your technical research identifies a genuine and documented incompatibility:

- Framework: Next.js with App Router
- Language: TypeScript
- Styling: Tailwind CSS

Database policy

Do not introduce a database in the initial version.

- The website must work without user registration or authentication.
- Comparison data should be processed without unnecessary permanent storage.
- Use appropriate caching to reduce repeated API requests.
- Only introduce additional infrastructure if there is a genuine technical requirement.

3. Clash of Clans API Integration — Mandatory RoyaleAPI Proxy

To resolve the official Clash of Clans API IP allowlisting restriction, use the RoyaleAPI Clash of Clans API Proxy as the primary intermediary for all Clash API requests.

The intended architecture is:

ClashIQ Backend → RoyaleAPI Proxy → Official Clash of Clans API

This is the required preferred integration architecture.

Requirements:

1. Route Clash of Clans API requests through the RoyaleAPI proxy instead of sending requests directly from Vercel to Supercell's API.
2. Research the current RoyaleAPI proxy documentation before implementation.
3. Verify its correct endpoint, authentication requirements, supported API endpoints, usage restrictions, and availability.
4. Confirm that the proxy supports all endpoints and data fields required by ClashIQ.
5. Keep API credentials and sensitive configuration exclusively on the server side.
6. Implement request timeouts, error handling, caching, and rate-limit handling.
7. Do not silently fall back to direct Supercell API requests if the proxy fails.
8. If the proxy has limitations, document them and identify a secure, compatible alternative.
9. Never use an unknown or untrusted proxy.

Important: RoyaleAPI Proxy is the required preferred architecture for resolving the IP restriction issue. Verify its actual capabilities and limitations before implementation, but do not switch to direct Vercel-to-Supercell requests without a documented technical reason.

4. API Research and Data Accuracy

Use the official Clash of Clans API as the primary source of player information, accessed through RoyaleAPI Proxy.

Before implementation:

- Research the official API documentation.
- Identify all relevant player fields.
- Determine which information is unavailable through the API.
- Verify the current game version.
- Check currently available troops, heroes, hero equipment, pets, buildings, spells, and other relevant entities.
- Do not rely on outdated game data or obsolete API fields.

Non-negotiable rules:

- Never fabricate player statistics.
- Never assume missing information is zero.
- Never guess troop or building levels.
- Clearly distinguish official API data from uploaded export data.
- Display Missing Data or Unavailable when information cannot be obtained.
- Show the last successful update time where appropriate.
- Handle incomplete API responses without breaking the entire interface.

6. Optional Export File Support

The official API does not expose every detail of a Clash of Clans account.

Therefore, support optional account export files to provide additional information, especially buildings, walls, and traps.

Requirements:

- Each player must have an independent optional upload field.
- Export files must not be mandatory.
- The website must remain fully functional without uploaded files.
- Support separate export files for both players.
- Research actual available export formats before implementing the parser.
- Do not assume that Supercell provides a universal official JSON export format for complete account data.
- Validate file structure, supported format, and player association whenever possible.
- Reject invalid or unsupported files with useful error messages.
- Prefer browser-side processing whenever practical.
- Do not send private account data to unnecessary external services.

Incomplete export scenarios

- No export files: perform the normal API-based comparison.
- Two valid export files: compare the additional available information.
- Only one export file: display that player's available information and show Missing Data for the other player.
- Never fabricate missing information or declare a winner when the comparison is not supported by the available data.

Clearly label every data source:

- Official API
- Uploaded Export

7. Account Strength Analysis

Create a dedicated Account Strength Analysis section.

This section must evaluate actual account progression and relative strength instead of simply declaring the account with the higher Town Hall the winner.

Include:

- Offensive Strength
- Defensive Strength
- Troop Progress
- Hero Progress
- Hero Equipment Progress
- Spell Progress
- Building Progress
- Overall Account Progress
- Town Hall-relative Progress
- Strengths and Weaknesses

Scoring methodology

Build a transparent and explainable scoring system.

Rules:

1. A higher Town Hall level does not automatically mean a stronger account.
2. Evaluate account progression relative to the maximum levels available at that account's Town Hall.
3. Use reasonable and explainable category weights.
4. Never compare raw levels without considering Town Hall progression.
5. Never treat missing information as zero.
6. Missing information must affect analysis confidence and data coverage, not automatically reduce the player's score.
7. Explain how each score is calculated.
8. Never present internally calculated scores as official Supercell statistics.

Display data coverage and analysis confidence alongside account scores.

When information is insufficient, show Incomplete or Insufficient Data instead of misleading precision.
